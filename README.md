# にゅりログ v1.0 ― 自分専用の創作管理手帳

Webアプリ・LoRA・NovelAI（NAI）の画風とプロンプト・オリジナルキャラクター（OC）・思いつきメモを、iPhoneの中だけで一元管理するPWA（ホーム画面に追加して使うWebアプリ）です。

- アカウント登録なし・無料・外部AI APIなし
- データはiPhone内（IndexedDB）にだけ保存。外部へ自動送信しない
- オフラインでも閲覧・編集・保存ができる
- いちばん大事にしているのは **データ保護**（ゴミ箱・変更履歴・下書き保護・ZIPバックアップと検査つき復元）

## すぐに試す（開発環境）

Node.js 20以上が必要です。

```bash
npm install
npm run dev          # http://localhost:5173 で起動（開発用・オフライン機能は無効）
npm test             # 自動テスト（ユニット・データ層）
npm run build        # 本番用ビルド（dist/ に出力）
npm run preview      # ビルド結果を確認
npm run e2e          # ブラウザ通しテスト（要 npm run build。Chromiumを使用）
npm run docs:json    # JSON仕様書とAI用依頼文を再生成
npm run icons        # アイコン再生成（Python + Pillow が必要）
```

## 公開（デプロイ）手順

ビルド結果（`dist/`）は静的ファイルだけなので、どこにでも置けます。既定では相対パス（`./`）でビルドするため、GitHub Pagesのサブパスでも独自ドメインでもそのまま動きます。

### A. GitHub Pages（GitHub Actionsで自動公開）

1. GitHubで新しいリポジトリ `nyuri-log` を作成（既存のリポジトリは変更しません）。
2. このフォルダの中身をプッシュ。
   ```bash
   git init && git add . && git commit -m "にゅりログ v1.0"
   git branch -M main
   git remote add origin https://github.com/nyuriwossan/nyuri-log.git
   git push -u origin main
   ```
3. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。
4. 同梱の `.github/workflows/deploy.yml` が動き、テスト → ビルド → 公開まで自動で行います。
5. 公開URL：`https://nyuriwossan.github.io/nyuri-log/`

> ⚠ GitHub Pagesの既存ドメイン（`nyuriwossan.github.io`）配下に置くと、他の自作アプリと**同じオリジン**になります。次の「公開先とプライバシーの注意」を読んでから決めてください。

### B. 別ホスト名で公開する（推奨候補）

他のアプリとオリジンを分けたい場合は、無料で別ホスト名を持てるサービスに `dist/` を置きます。

- **Cloudflare Pages**：GitHubリポジトリを連携 → Build command `npm run build`、Output directory `dist` → `https://nyuri-log.pages.dev` のようなURLになる
- **Netlify**：同様に Build command `npm run build`、Publish directory `dist`
- **GitHub Pages＋独自ドメイン**：独自ドメイン（有料）をこのリポジトリだけに割り当てる

どれも設定の変更は不要です（`BASE_PATH` は既定の `./` のまま）。特別な事情で絶対パスにしたい場合は `BASE_PATH=/nyuri-log/ npm run build` のように指定できます。

> 公開先を後から変えると、**ブラウザ上は別のアプリ扱い**になり、データは引き継がれません。移行するときは、旧URLでバックアップを作り、新URLで復元してください。

## iPhoneでホーム画面に追加する

1. iPhoneの **Safari** で公開URLを開く
2. 画面下の **共有ボタン**（四角から上向き矢印のアイコン）を押す
3. **「ホーム画面に追加」** → 「追加」
4. 以後はホーム画面の「にゅりログ」アイコンから開く

**大切な注意**：iPhoneでは、Safariで開いたにゅりログと、ホーム画面から開いたにゅりログで保存場所が分かれることがあります。ふだんは**ホーム画面のアイコンからだけ**開いてください。Safariで書いたものを移すときは、Safari側でバックアップ → ホーム画面アプリ側で復元します。初回起動時の案内にも同じことを表示しています。

## バックアップと復元の操作

### バックアップを作る

1. 設定 → **バックアップと復元** → **バックアップZIPを作成**
2. 「ZIPファイルを作成しました」と出たら **保存・共有** を押す
3. iPhoneの共有シートで **「"ファイル"に保存」** → iCloud Drive などを選ぶ
4. 「ファイル」アプリでZIPがあることを確認したら、**「ファイル」アプリで確認した** を押す（任意）

- このアプリは「ZIPを作った」「共有シートに渡した」までしか分かりません。iCloud Driveに保存できたかは確認できないため、「iCloud保存済み」とは表示しません。
- 画像の合計が設定の上限（既定150MB）を超えると、自動で `_part1of3.zip` のように分割します。**全部のファイルを保存してください。**
- 前回から7日以上たつか、10件以上変更すると、ホームに控えめな案内が出ます（×で3日間非表示）。日数・件数は設定で変えられます。

### 復元する（追加復元＝既定）

1. 設定 → バックアップと復元 → **ZIPファイルを選ぶ**（分割の場合は同じ日時のファイルをまとめて選択）
2. 形式・バージョン・チェックサムを自動で検査し、**復元内容のプレビュー**（件数、新規、既にある記録、不足画像）を表示
3. 同じ記録の扱い（スキップ／別記録として追加）を選び、**追加復元する** → 最終確認

追加復元は、今あるデータを**削除も上書きもしません**。書き込みは1つのトランザクションで行うため、途中で失敗した場合は何も書き込まれず、元のままです。分割ファイルの一部だけを先に復元し、残りを後から追加復元しても画像がそろいます。

### 全置換で復元する（上級者向け）

「全置換で復元する」を開き、次の順で操作します。

1. **今のデータをバックアップして保存**（必須。これを済ませないと実行ボタンが押せません）
2. **全置換を実行** → 二重確認（2回目は「置き換える」と入力）

全置換も1トランザクションで、失敗すれば元のデータが残ります。分割バックアップの一部しか選んでいない場合は全置換できません。

## 公開先とプライバシーの注意

- **アプリの画面（プログラム）は公開されます。** GitHub Pagesに置くと、URLを知っている人は誰でもアプリを開けます。ただし開いた人の端末には**その人のデータしか**ありません。あなたの記録は、あなたのiPhoneの中にだけあります。
- **リポジトリに個人データは入りません。** データはIndexedDB（端末内）に保存され、ソースコードにもビルド結果にも含まれません。秘密のAPIキーや認証トークンも埋め込んでいません。
- **外部への通信はGitHub APIだけ**です（一括登録で公開リポジトリ一覧を取るとき。認証なし）。Content-Security-Policy で通信先を自分のサイトと `api.github.com` に制限しています。
- **同一オリジンについて**：`nyuriwossan.github.io/nyuri-log/` と `nyuriwossan.github.io/他のアプリ/` は同じオリジンです。同じオリジン内のページは、互いのIndexedDBを技術的には読めます。自作アプリだけなら実害は小さいですが、他のアプリで外部スクリプトを読み込んでいる場合などに備え、別ホスト名（上記B）での公開も選べるようにしています。
- **バックアップZIPは暗号化されていません。** パスワード・個人情報などの秘密情報を保存する用途には向きません。ZIPの保管場所（iCloud Driveなど）の安全性に依存します。

## 設計上の判断とその理由

| 判断 | 理由 |
|---|---|
| ハッシュ方式のURL（`#/r/…`） | GitHub Pagesのサブパスや別ホストで、再読み込み時に404にならないため |
| 相対パスでビルド（`base: './'`） | 公開先を後から決められるように（指示書2章） |
| 画像は ArrayBuffer として別テーブルに保存 | 古いiOS SafariでBlobをIndexedDBに入れる不具合が過去にあったため、最も互換性の高い形式にした。メタ情報・軽量化画像・サムネイル・元画像を別々のテーブルに分け、一覧ではサムネイルだけを読む |
| 画像は常に再エンコード | EXIFの向きを反映し、位置情報などのメタデータを取り除くため。透過があればWebP（非対応ならPNG）、なければJPEG |
| 画像の参照は「記録・履歴・下書きのどれかに残っている限り消さない」 | 履歴から戻したときに画像が消えている事故を防ぐため。参照がなくなった画像は、完全削除・履歴の整理時に即時、編集中断の残りは24時間後に整理 |
| 履歴は「保存ボタン1回＝1版」、内容が変わらない保存では版を増やさない | 1文字ごとに増やさないため（指示書9-3） |
| 保存の完了はトランザクション成功で判定 | 書き込み失敗を「保存済み」と表示しないため。失敗時は入力内容を残し「再試行」を出す |
| 下書きは入力停止0.7秒後＋画面を離れる瞬間に保存 | iPhoneでアプリが急に閉じられても失わないため |
| アプリ更新は「更新する」ボタンで適用 | 入力中に勝手に再読み込みされないため。更新で入れ替わるのはアプリ本体のキャッシュだけで、IndexedDBには触れない |
| DBスキーマは版を足していく方式（Dexie） | 既存の版定義を消さず、移行は補完のみ（非破壊）。将来版での開き直しをテストで確認済み |
| GitHub登録時、制作日・ステータスは空欄 | リポジトリ作成日≠制作日（指示書7章）。作成日は「リポジトリ作成日」として別項目に保存 |
| GitHub登録時、公開URLは「GitHubにホームページURLが登録されている場合だけ」 | GitHub Pagesが有効でもURLを推測で入れない（プレビューで注記のみ） |
| GitHub一覧の初期選択は「なし」、フォークは非表示 | 勝手に全件登録しないため |
| JSONの重複判定は「同カテゴリー同タイトル」「同GitHub URL」「同公開・配布URL」 | AIの出力にはIDが無いため、利用者が見て分かる基準にした。重複候補は初期状態で選択を外す |
| JSONで未知の項目は保持 | 指示書8章。未知の `fields` キーは記録の `fields` に、未知の共通キーは `extra.importUnknown` に残し、詳細画面の「その他の項目」に表示 |
| ステータス「未設定」を許可 | GitHub登録時に推測しないため。カテゴリーの候補にない値も消さずに保持 |
| バックアップ忘れの案内：初回は記録3件以上で表示 | まだ一度もバックアップしていない状態が一番危ないため |
| バックアップの分割上限 既定150MB | iPhoneのSafariはZIPをメモリ上で組み立てるため、大きすぎると失敗しやすい。設定で変更可 |
| 元画像の保存は既定オフ、オンにする時は容量増加を明示 | 指示書5章 |
| SVG画像は登録不可 | スクリプトを含められる形式のため（安全性） |
| 検索は全件をメモリ上で絞り込み | 個人利用の件数（数千件程度）なら十分速く、日本語の部分一致・全角半角の吸収が簡単なため |

## 既知の制約・未検証事項

### 実機iPhoneでの確認が必要（未検証）

以下は開発環境（Linux上のChromium）では確認できず、**未検証**です。

- iOS Safari／ホーム画面アプリでの全体の動作・見た目・セーフエリア（ノッチ・ホームバー）
- 写真ライブラリからの選択、iPhone撮影のHEIC写真の扱い（写真ライブラリ経由ならiOSが自動でJPEGに変換することが多い見込み。変換できない場合はエラー表示を実装済み）
- iOS Safariで透過画像をWebPに書き出せるか（できない場合はPNGに自動で切り替える実装。Chromiumでは WebP になることを確認済み）
- 共有シートでの「"ファイル"に保存」→ iCloud Driveへの保存（Chromiumではダウンロード方式で確認）
- iPhoneのメモリでの大きなバックアップ（数百MB）の作成・復元
- ホーム画面アプリのオフライン起動、アプリ更新の通知
- `navigator.storage.persist()` が許可されるか（WebKitは、ホーム画面アプリとして開いているかなどの条件で判断するとしています）
- 実際の容量不足（QuotaExceededError）時の表示（エラー処理はテストで模擬して確認済み）
- 実際のGitHub APIへの接続（応答を模擬して確認済み。レート制限は認証なしで1時間あたり60回程度）

### 仕様上の制約

- **データはこの端末・このブラウザの中だけ**です。複数端末の同期はありません（データ構造は将来の拡張を妨げないようにしています）。
- **Safariとホーム画面アプリでデータが分かれる場合があります**（上記「ホーム画面に追加する」参照）。
- **保存領域の自動削除**：WebKitは、端末の容量が逼迫したときや、サイトがしばらく使われていないときに、保存データを自動削除することがあります。2020年のWebKitの説明では、ホーム画面に追加したWebアプリはSafariとは別扱いで、使用日数の数え方も別、通常は削除を想定していないとされています。ただし将来の仕様変更もありうるため、**バックアップを前提**にしてください。
- **アニメーションGIF**は1枚目の静止画として保存されます。
- iPhoneの容量上限：WebKitの説明では、ホーム画面アプリなどブラウザ以外のアプリはディスク容量の最大15%程度までがサイトごとの上限です。超えると保存に失敗し、アプリはそのことを表示します。
- 変更履歴は記録ごとに直近20版（設定で1〜100）。それより古い版は消えます。
- ゴミ箱は自動では空になりません。

```
  lib/aiPrompt.ts     AI用依頼文・仕様書の生成
  lib/search.ts       検索・絞り込み・並び替え
  views/              各画面
  components/         共通部品（カード、画像、入力欄、通知）
tests/                ユニット・データ層テスト（Vitest）
e2e/                  ブラウザ通しテスト（Playwright + Chromium）と画像素材

```
